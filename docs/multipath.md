# Задача для Cursor: несколько путей родства и пометка общих предков

Действуй согласно `docs/PLAN.md`. Это доработка модуля родства под сёла с
близкородственными браками, где между двумя людьми часто есть не один путь
родства, а несколько.

## Зачем это нужно

Сейчас `findKinship` в `lib/kinship.ts` находит **только один кратчайший путь**
между двумя людьми (через BFS в функции `shortestPath`). Но при близких браках
(двоюродные поженились и т.п.) два человека связаны сразу несколькими путями —
например, «троюродные по отцу И одновременно свояки по матери». Эта
множественность — ценная информация, которую в селе знают и помнят, и её нужно
показывать, а не терять.

Отдельно: когда один и тот же предок оказывается предком человека несколькими
путями (эффект «схлопывания родословной», pedigree collapse), такого предка надо
уметь пометить — «встречается в родословной дважды».

## Важное ограничение (прочитай перед реализацией)

Искать **все** пути в графе нельзя — на плотном графе с петлями их могут быть
тысячи, и это повесит сервер. Поэтому задача — найти **несколько значимых
независимых путей с жёсткими лимитами**, а не все пути вообще. Конкретные лимиты
заданы ниже. Не превышай их и не убирай ради «полноты» — они защищают от
зависания.

## Что сделать

### 1. Не ломать существующее

Функция `findKinship` уже используется в `lib/people.ts` (`getKinship`) и в API
`app/api/kinship/route.ts`, а её результат читает компонент
`components/kinship-finder.tsx`. Поэтому:

- Сохрани текущую сигнатуру и поведение `findKinship` без изменений — она и
  дальше возвращает **основной (кратчайший) путь** в полях `relation`,
  `sentence`, `steps`, как сейчас.
- Всю новую логику добавь **рядом**, не переписывая рабочий код. Существующие
  функции `shortestPath`, `unwind`, `describeBlood`, `inLawRelation`,
  `bloodRelation` и словарь терминов не трогай — переиспользуй их.

### 2. Новая функция поиска нескольких путей

Добавь функцию `findAllKinshipPaths(graph, fromId, toId)` со следующим
поведением:

- Ищет несколько **простых** путей (без повторяющихся людей внутри одного пути)
  между `fromId` и `toId`.
- Жёсткие лимиты, ровно такие:
  - максимальная длина пути — **8 шагов** (длиннее не искать);
  - максимум путей в результате — **6** (нашёл 6 — останавливайся);
  - общий предохранитель по числу просмотренных узлов — **50 000** (достиг —
    прекращай поиск и возвращай, что уже нашёл).
- Пути должны быть **разными** — не возвращай один и тот же набор людей в другом
  порядке. Считай путь уникальным по упорядоченной последовательности id людей.
- Для каждого найденного пути сформируй название родства, переиспользуя уже
  существующие `describeBlood` и `inLawRelation` (как это делает нынешняя
  `findKinship`).
- Возвращай пути **отсортированными от короткого к длинному**. Первый в списке
  должен совпадать с тем, что возвращает обычная `findKinship`.

Тип результата примерно такой (уточни под свой стиль в проекте):

```ts
export type KinshipPath = {
  relation: string;        // название родства для этого пути
  steps: KinshipStep[];    // шаги пути, как в KinshipResult
};

export type MultiKinshipResult = {
  from: PersonDTO;
  to: PersonDTO;
  primary: KinshipPath;        // основной (кратчайший) — совпадает с findKinship
  alternates: KinshipPath[];   // остальные значимые пути, без повтора primary
};
```

Если путей несколько, `alternates` содержит все, кроме `primary`. Если путь
один — `alternates` пустой. Если пути нет вовсе — верни `{ error }`, как это
делает `findKinship`.

### 3. Пометка общих предков (pedigree collapse)

Добавь функцию `findDoubledAncestors(graph, personId)`, которая находит предков,
входящих в родословную человека **больше чем одним путём** по линиям
родителей (только шаги «вверх», т.е. `parent`; браки не считаем).

- Идём вверх от `personId` по всем родителям, считая, сколькими **различными
  путями** достигается каждый предок.
- Возвращаем список тех предков, у кого путей больше одного, с указанием числа
  путей.
- Тот же предохранитель по числу узлов (**50 000**) и по глубине (**8
  поколений**), чтобы не зависнуть.

Тип примерно:

```ts
export type DoubledAncestor = {
  person: PersonDTO;
  pathCount: number;   // сколькими путями этот предок входит в родословную
};
```

### 4. Ничего не менять во фронтенде и API в рамках этой задачи

Это чисто серверная доработка `lib/kinship.ts`. Экспортируй новые функции и типы,
но **не подключай их** пока к API и компонентам — это отдельный следующий шаг.
Так проще проверить, что ничего не сломалось.

## Как проверить, что готово

1. `npm run dev` запускается без ошибок сборки и типов.
2. Раздел «Родство» на сайте работает как раньше — старая `findKinship` не
   изменила поведение.
3. Попроси Cursor написать короткий временный скрипт или тест, который на
   маленьком примере (двое двоюродных, у которых поженились родители, — классика
   близкого брака) вызывает `findAllKinshipPaths` и печатает найденные пути.
   Убедись, что путей возвращается **больше одного**. После проверки временный
   скрипт можно удалить.
4. На том же примере `findDoubledAncestors` для общего ребёнка возвращает
   непустой список — общий предок помечен как входящий двумя путями.

## Границы задачи

- Не переписывай рабочую `findKinship`.
- Не подключай новые функции к API и UI — это следующий шаг.
- Не снимай и не увеличивай лимиты (8 шагов, 6 путей, 50 000 узлов).
- Не пытайся искать «все пути без ограничений» — это осознанно исключено.
